# RankMatrix search visibility research and product comparison

> Historical snapshot: see [24 October PR review and remaining findings](SEO-PR-LINE-REVIEW.md) for later quota, metadata, content, contract and performance corrections. Earlier test counts and implementation descriptions are not the final release state.

Research date: 23 October 2026.

RankMatrix's largest immediate opportunity is to publish the rendering, indexing and metadata work already in review. After that, the strongest product opportunities are trustworthy data releases, correct comparisons, useful answers derived from the data, and evidence that students actually reach their answers. Small presentation improvements matter, but their expected value differs greatly from removing an indexing barrier.

This comparison covers the deployed website, the local code through frontend PR #27 and backend PR #16, public SEO endpoints, and current first-party search documentation. It distinguishes technical eligibility, relevance and quality, search appearance, usability, and measurement. These are not interchangeable ranking factors. Priorities below are engineering judgments, not disclosed search-engine weights. No implementation can guarantee first place for every related query.

## Research conclusions that change earlier assumptions

Google can render JavaScript, so client rendering does not automatically make a site invisible. However, server-rendered text reduces dependence on rendering and supports crawlers that do not execute JavaScript. Our empty initial catalogue responses are a concrete reason to improve rendering, rather than an explanation of all ranking problems. See [JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Current Google guidance says there is no special AI schema or required `llms.txt`; it explicitly says Google Search ignores that file. It rejects an ideal AI page length and advises against creating pages for every query variation. RankMatrix should invest in its underlying information and usefulness. See [Google's generative AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

There are two important 2026 account-level changes. Google documents a Search generative AI inclusion control in Search Console, defaulting to inclusion unless overridden/inherited. Its separate generative AI performance report can be absent when impressions are insufficient. Verify both for our property. See [inclusion control](https://support.google.com/webmasters/answer/16908024) and [performance report](https://support.google.com/webmasters/answer/16984139).

Google's current changelog says FAQ rich results stopped appearing from 7 May 2026 and the documentation was removed in June. The older government/health-only eligibility explanation is historical. Keep useful visible FAQs, but assign no Google FAQ rich-result benefit to the markup. This supersedes the older FAQ eligibility framing in our earlier audit. See [May and June 2026 documentation updates](https://developers.google.com/search/updates).

## Tactics that should not consume this project

| Claim or tactic                                                               | Evidence and decision for RankMatrix                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add hundreds of meta keywords                                                 | Google ignores the meta-keyword tag. Keep natural relevant copy. [Supported meta tags](https://developers.google.com/search/docs/crawling-indexing/special-tags)                                                                                                                  |
| Set a keyword density, ideal article length or exact heading count            | There is no magic word-count target. Write enough to answer the task clearly; headings serve readers. [SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)                                                                               |
| llms.txt will raise Google AI rankings                                        | Current Google documentation explicitly says it ignores the file. Existing file can remain for other consumers; do not prioritize it. [AI guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)                                                    |
| FAQ schema wins expandable Google answers                                     | Google retired that rich result in May 2026. Keep useful FAQs, assign no expected display gain. [Changelog](https://developers.google.com/search/updates)                                                                                                                         |
| A perfect Lighthouse SEO score proves strong SEO                              | It is a bounded automated check. Our deployed site scored 100 while exposing an empty catalogue and poor layout stability. Measure indexing, relevance and outcomes.                                                                                                              |
| IndexNow or Google's Indexing API guarantees immediate indexing               | IndexNow notifies participating engines. Google's general Indexing API is limited to eligible job/livestream pages, not JoSAA tools. [IndexNow](https://www.indexnow.org/documentation), [Google API scope](https://developers.google.com/search/apis/indexing-api/v3/quickstart) |
| Buy links, forum mentions or click traffic                                    | Avoid manipulative links, spam and fabricated engagement. Spend on useful resources and legitimate distribution. [Spam policies](https://developers.google.com/search/docs/essentials/spam-policies)                                                                              |
| Every rank, category, year and keyword needs a page                           | Create distinct pages only when they provide independent utility and actual data. Duplicate combinations create maintenance and quality risks. [AI guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)                                        |
| Advertising spend or AdSense approval improves organic position               | Treat monetization separately. No evidence here supports either as an organic ranking intervention. Protect content access and experience.                                                                                                                                        |
| Social preview tags, ARIA, a PWA or a new domain are automatic ranking boosts | Use social/accessibility features for their real purposes. No domain move, PWA or framework migration is justified by this research.                                                                                                                                              |

## Boundaries of the findings

No Search Console, Bing Webmaster Tools or GA4 property was accessed for this research. Current search queries, rankings, penalties, selected canonicals, backlink quality and AI impression counts therefore remain verification tasks, not diagnosed failures. The small public search sample is illustrative. Full dynamic-page crawling, official row-by-row reconciliation, actual provider-origin bot access, field performance, and deployment checks remain separate work. The report links first-party documentation for engine behavior and treats product design recommendations as judgments to validate with users and data.
